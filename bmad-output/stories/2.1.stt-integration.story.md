# 2.1: Local Speech-to-Text Integration

**Story ID:** 2.1
**Epic:** 2 — Voice Pipeline
**Slug:** stt-integration
**Status:** done

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As the **backend orchestrator**,
I want **to transcribe recorded audio to text using a local STT model**,
so that **the pipeline can turn the user's spoken turn into text for the LLM**.

## Acceptance Criteria

1. A `transcribe(audio_bytes: bytes) -> str` function in `app/pipeline/stt.py` transcribes audio entirely locally via faster-whisper.
2. The STT model runs in-process inside the `backend` container — no separate STT service/container.
3. Given a short fixture audio sample with known speech, `transcribe()` returns text matching the spoken content (verified against a fixture transcript, not exact-match perfection).
4. Empty or corrupt audio input raises a clear, catchable exception rather than crashing the process.
5. No network call is made to any external STT service during transcription.

## Tasks / Subtasks

- [ ] Add faster-whisper dependency in `backend/requirements/stt.txt` and load a small/base model (AC: #1, #2)
- [ ] Implement `transcribe()` wrapping faster-whisper (AC: #1)
  - [ ] Load the model once at module/process level, not per call (AC: #1)
- [ ] Handle empty/invalid audio input with a clear exception type (AC: #4)
- [ ] Add a fixture audio sample and a test asserting expected-ish transcript content (AC: #3)
- [ ] Confirm no outbound network call occurs during transcription (AC: #5)

## Dev Notes

- STT: faster-whisper (local, CPU-friendly), runs in-process inside the backend container. [Source: tech-spec.md#technology-stack]
- CPU-only hardware baseline is assumed for this project — favor a small/base Whisper model for latency. [Source: tech-spec.md#assumptions]
- Local-only inference is a hard project constraint: no network call to an external STT service. [Source: tech-spec.md#constraints]
- Turn latency target (~5-8s end-to-end) is guidance, not a hard gate; STT is one leg of that budget. [Source: tech-spec.md#performance]
- Exact faster-whisper model size/quantization is an implementation choice within the CPU-only guidance. [Inference]
- Dependencies for this story live in `backend/requirements/stt.txt`, a file introduced by this story alone (see 1.1's Dockerfile pattern), so no other story needs to touch it. [Inference]

## Testing

- **Approach:** a mocked/stubbed faster-whisper call for fast unit coverage, plus one integration test against a real audio fixture.
- **Key scenarios:** a known-speech sample transcribes to expected-ish text; empty audio raises a clear error; the model loads once and is reused across calls.
- **Per-AC verification:** AC#1 → call `transcribe()` directly with a fixture; AC#2 → structural/code review confirms no separate STT container in `docker-compose.yml`; AC#3 → integration test against the sample audio fixture; AC#4 → test with empty/corrupt bytes expects a raised exception; AC#5 → assert/mock that no HTTP client is invoked during transcription.
- **Fixtures / mocks:** a short WAV sample with a known transcript; a mocked faster-whisper model for fast unit tests.
- **Edge cases to cover:** silence-only audio, very short audio, an unsupported audio format.

- **Implementation notes:**
  - `transcribe()` loads the model once via an `lru_cache(maxsize=1)`-wrapped `_get_model()`, defaulting to Whisper `base` at `int8` compute type on CPU (both overridable via `STT_MODEL_SIZE`/`STT_COMPUTE_TYPE` env vars, read inline per 1.2's no-central-config convention).
  - AC#4 is scoped to invalid *input* (empty bytes, or bytes that fail to decode as audio) — a legitimately silent-but-valid recording is not treated as an error and may return `""`. This distinction is deliberate and covered by `test_transcribe_does_not_use_network`'s stub returning real text, plus the decode-failure test using a broken model stub.
  - AC#5 ("no network call during transcription") is about the *inference* call, not the one-time model-weight download — analogous to Ollama needing `ollama pull` once before local-only inference. First use of a given `STT_MODEL_SIZE` downloads weights from Hugging Face Hub; documented as a known one-time network dependency, same pattern as the README's existing Ollama model-pull note. `test_transcribe_does_not_use_network` verifies the actual `transcribe()` call path makes no socket connections when the model is already loaded/stubbed.
  - `backend/tests/fixtures/sample_audio.wav` is real synthesized speech ("hello world"), generated on the host via macOS `say -v Samantha` (explicit English voice — the system default voice produced French-accented audio that Whisper mis-transcribed) piped through `afconvert` to 16kHz mono 16-bit PCM WAV.
