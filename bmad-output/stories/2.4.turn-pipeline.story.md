# 2.4: End-to-End Turn Pipeline

**Story ID:** 2.4
**Epic:** 2 — Voice Pipeline
**Slug:** turn-pipeline
**Status:** ready-for-dev

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **user**,
I want **one backend endpoint that takes my recorded audio and returns the AI's scenario-aware spoken reply and transcript**,
so that **the frontend has a single call to drive a full conversation turn**.

## Acceptance Criteria

1. `POST /api/session/{id}/turn` accepts recorded audio for an active session and returns the user's transcript, the AI's reply transcript, and the AI's reply audio.
2. The endpoint composes the LLM prompt from the session's scenario persona/goal (via 3.1's schema and 3.3's session/scenario lookup) plus prior turns — not a generic prompt.
3. The endpoint calls, in order, `transcribe()` (2.1) → prompt composition → `generate_reply()` (2.2) → `synthesize()` (2.3), returning the combined result.
4. The completed turn (user text, AI text) is appended to the session's in-memory history after each call.
5. A failure at any pipeline stage (STT/LLM/TTS) returns a clear error response rather than a partial or broken result.

## Tasks / Subtasks

- [ ] Implement `POST /api/session/{id}/turn`, registered on `app/api/router.py` (AC: #1)
- [ ] Compose the scenario-aware prompt from the session's scenario config + `.history` (AC: #2)
- [ ] Call STT → LLM → TTS in sequence in `app/pipeline/turn.py`, assembling the response (AC: #3)
- [ ] Append the completed turn to `session.history` via the session object from 3.3 (AC: #4)
- [ ] Add per-stage error handling and a clear error response shape (AC: #5)
- [ ] Integration test covering the full turn end-to-end (AC: #1-#5)

## Dev Notes

- Backend Orchestrator coordinates a conversation turn end-to-end and holds per-session state. [Source: tech-spec.md#backend-orchestrator-faststapi]
- Endpoint contract: `POST /api/session/{id}/turn` — submit recorded audio, receive transcript + AI audio for that turn. [Source: tech-spec.md#backend-orchestrator-faststapi]
- Scenario Engine composes the system prompt from persona, goal, target language, and prior turns. [Source: tech-spec.md#scenario-engine]
- No persistent database — conversation history lives in backend process memory for the session's lifetime. [Source: tech-spec.md#data-model]
- Turn latency target (~5-8s end-to-end) applies to this full sequential call chain. [Source: tech-spec.md#performance]
- Error handling should surface clear, user-facing-friendly status per the project's Error Handling Strategy. [Source: tech-spec.md#error-handling-strategy]
- Push-to-talk (record-then-send), not live streaming, for this endpoint. [Source: tech-spec.md#risks--mitigations]
- This story imports `get_session()` from 3.3's `session_store.py` and mutates `session.history` directly from within `turn.py`; it does not edit `session_store.py` itself. [Inference — keeps Owned Scope disjoint from 3.3]

## Testing

- **Approach:** an integration test exercising the full route with fixture audio and a real scenario config, mocking or using real STT/LLM/TTS depending on the test environment.
- **Key scenarios:** a full turn returns transcript + reply + audio for a valid session; a mid-sequence failure (e.g. Ollama down) returns a clear error, not a partial success; two turns in a row show growing history influencing the second reply.
- **Per-AC verification:** AC#1 → integration test hits the route, asserts the response shape; AC#2 → assert the prompt sent to `generate_reply()` includes the scenario's persona/goal; AC#3 → verify call order via test doubles/spies; AC#4 → assert `session.history` grows after each call; AC#5 → simulate each stage failing independently, assert a clear error response for each.
- **Fixtures / mocks:** fixture audio plus a real scenario config from 3.2; mocked STT/LLM/TTS for fast tests, one slower real-pipeline integration test.
- **Edge cases to cover:** a session id that doesn't exist; a turn submitted after the session already ended; a very long conversation history.
