# 3.2: Starter Scenario Content

**Story ID:** 3.2
**Epic:** 3 — Scenarios
**Slug:** starter-scenarios
**Status:** done

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **user**,
I want **3-5 ready-made practice scenarios covering common situations**,
so that **I have real content to practice with from day one**.

## Acceptance Criteria

1. At least 3, up to 5, scenario YAML files exist under `backend/scenarios/`, each conforming to the 3.1 schema.
2. Scenarios cover distinct situations, at minimum: restaurant ordering, a job interview, and small talk; directions and shopping are included if time allows.
3. Each scenario's `persona_prompt` gives the LLM enough context to stay in character and pursue the scenario's `goal` across multiple turns.
4. All scenario files load successfully through the 3.1 loader with zero validation errors.
5. Each scenario declares the same `target_language`, consistent with the single-target-language assumption in tech-spec.md.

- [ ] Author the small-talk scenario YAML (AC: #1, #2, #3, #5)
- [ ] Author the directions and shopping scenario YAML files if time allows (AC: #1, #2, #3, #5)

## Testing

- **Approach:** no new test code — reuse 3.1's loader tests by pointing them at the real `backend/scenarios/` directory.
- **Key scenarios:** the real scenario set loads with zero validation errors; each scenario has a non-trivial, distinct `persona_prompt` and `goal`.
- **Per-AC verification:** AC#1, #4 → run the 3.1 loader against `backend/scenarios/`, assert no errors and the expected file count; AC#2 → manual review of scenario titles/topics for coverage; AC#3, #5 → manual review of each `persona_prompt` and `target_language` field.
- **Fixtures / mocks:** none — these files ARE the real fixtures 2.4, 3.3, and 4.1 will use.
- **Edge cases to cover:** a scenario whose `goal` could be satisfied in one turn should still support a multi-turn conversation gracefully.
