# 4.2: Live Transcript Display

**Story ID:** 4.2
**Epic:** 4 — Frontend
**Slug:** live-transcript
**Status:** ready-for-dev

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **user**,
I want **a running text transcript of both sides of the conversation**,
so that **I can follow along with and review what was said, not just rely on audio**.

## Acceptance Criteria

1. A transcript panel is visible in the UI throughout an active session.
2. After each turn, the user's transcribed text and the AI's reply text (both returned by `POST /api/session/{id}/turn`) are appended to the panel in order.
3. The transcript panel auto-scrolls to show the latest turn.
4. Each entry is visually labeled by speaker (user vs. AI).
5. The transcript clears when a new session starts.

## Tasks / Subtasks

- [ ] Build `frontend/components/transcript.js` rendering a labeled, ordered turn list (AC: #1, #4)
- [ ] Hook transcript updates into the turn-response handling in `frontend/app.js` (AC: #2)
- [ ] Add auto-scroll to the latest entry (AC: #3)
- [ ] Clear transcript state on new session start (AC: #5)

## Testing

- **Approach:** manual browser testing alongside 4.1's golden-path walkthrough.
- **Key scenarios:** each completed turn appends both a user and an AI entry, correctly labeled and ordered; the panel scrolls to the newest entry; starting a new session clears prior transcript entries.
- **Per-AC verification:** AC#1 → manual load, confirm panel is present; AC#2 → manual turn, confirm both entries appear with correct text; AC#3 → manual multi-turn session, confirm scroll follows the latest entry; AC#4 → visual check of speaker labeling; AC#5 → start a second session, confirm the panel is empty before the first new turn.
- **Fixtures / mocks:** none required — exercised against the real backend running via `docker compose up`.
- **Edge cases to cover:** very long individual turns (text wrapping); rapid consecutive turns.
