# 6.1: Choose the Practice Language on the Main Menu

**Story ID:** 6.1
**Epic:** 6 — Multi-Language Support
**Slug:** multi-language-support
**Status:** review

> Added after the original 13-story backlog completed, as a deliberate
> correction to tech-spec.md's single-language assumption. Sized to one
> dev-day (~2-8h). No story points.

## Story

As a **user**,
I want **to choose which language I'm practicing on the main menu**,
so that **the AI speaks that language back to me instead of always English**.

## Acceptance Criteria

1. `GET /api/languages` returns the supported practice languages, each with a code and a display label.
2. The main menu forces a language choice: the "Start session" button stays disabled until both a language and a scenario are selected.
3. `POST /api/session/start` requires a `language`, rejects an unsupported one with a clear 4xx error, and stores the chosen language on the session.
4. The LLM prompt instructs the AI to speak the session's chosen language and to stay in it, rather than using the scenario file's `target_language` field.
5. The AI's spoken reply uses a TTS voice matching the chosen language, not always the English voice.
6. Speech-to-text is given the chosen language as a hint rather than relying on auto-detection.

## Tasks / Subtasks

- [ ] Add a language registry mapping code → display label + Piper voice (AC: #1, #5)
- [ ] Add `GET /api/languages`, registered on `app/api/router.py` (AC: #1)
- [ ] Accept + validate `language` on `POST /api/session/start`; store it on the session (AC: #3)
- [ ] Use the session's language in the composed prompt (AC: #4)
- [ ] Select the TTS voice per language, caching each voice separately (AC: #5)
- [ ] Pass the language to `transcribe()` as a Whisper hint (AC: #6)
- [ ] Add a language selector to the main menu and gate the start button on it (AC: #2)

## Dev Notes

- This story deliberately reverses tech-spec.md's "initial release targets one practice language" assumption, which was flagged from the start as made **without user confirmation**. [Source: tech-spec.md#assumptions]
- Piper voices are language-specific — speaking French needs a French voice model, so a per-language voice map is required, not just a prompt change. Voice availability per language was already called out as a project risk. [Source: tech-spec.md#risks--mitigations]
- Voice models download lazily on first use (established in 2.3's implementation), so offering more languages costs nothing until one is actually used. [Inference]
- faster-whisper accepts a `language=` hint; without it the model auto-detects, which was observed during 2.1's implementation to mis-transcribe accented speech into the wrong language entirely. [Inference — observed during story 2.1 fixture work]
- The scenario schema's `target_language` field (from 3.1) becomes vestigial for prompt purposes: the scenarios are language-neutral role-plays (a waiter, an interviewer), so the session's chosen language wins. The field is intentionally left in the schema to avoid a breaking change to 3.1/3.2's contract. [Inference]
- Session state stays in-memory per session, consistent with the no-database approach. [Source: tech-spec.md#data-model]

## Testing

- **Approach:** unit + integration tests against the FastAPI `TestClient`, plus a real end-to-end check that a non-English session actually produces non-English audio.
- **Key scenarios:** the languages endpoint lists the registry; starting a session without a language is rejected; starting with an unsupported language returns a clear 4xx; the composed prompt names the chosen language; TTS resolves a different voice per language; the STT hint is passed through.
- **Per-AC verification:** AC#1 → GET the endpoint, assert shape; AC#2 → manual browser check of the disabled start button; AC#3 → POST with a missing/bogus language, assert 4xx, and assert a valid one is stored on the session; AC#4 → capture the prompt sent to the LLM, assert it names the language; AC#5 → assert the voice resolved for two different languages differs; AC#6 → assert `transcribe()` receives the session's language.
- **Fixtures / mocks:** mocked STT/LLM/TTS for fast tests, reusing the patterns from 2.4's tests; one slower real check for a non-English session.
- **Edge cases to cover:** a session started before the languages list loads; an unsupported language code; a language whose voice has not been downloaded yet.

## Dev Agent Record

- **Completed:** 2026-09-02 (implementation); status left at `review`, not `done` — the browser-side forced-choice UX (AC#2) still needs a human pass, same limitation as every other frontend story this session.
- **Files added:** `backend/app/languages.py`, `backend/app/api/languages.py`, `backend/tests/test_languages.py`
- **Files edited:** `backend/app/api/router.py`, `backend/app/api/session_start.py`, `backend/app/state/session_store.py`, `backend/app/pipeline/{turn,tts,stt}.py`, `frontend/index.html`, `frontend/components/scenario_picker.js`, `frontend/app.js`, `frontend/styles.css`, plus signature updates in `backend/tests/test_{stt,tts,turn,session_api}.py`.
- **Implementation notes:**
  - `languages.py` is the single registry: code → English label (used in the prompt), native label (used in the picker), and Piper voice. Adding a language is a one-line edit; voices download lazily, so listing seven costs nothing until one is used. All seven voice names were verified against the live Piper `voices.json` before wiring them in.
  - `_get_voice()` is now keyed by voice name with `lru_cache(maxsize=len(LANGUAGES)+1)` instead of `maxsize=1`, so alternating between languages doesn't thrash the cache. `TTS_VOICE`/`TTS_VOICE_DIR` env overrides still work for the no-language case, preserving 2.3's original behavior.
  - `transcribe()` now takes a `language` hint passed to Whisper instead of relying on auto-detection — this matters more than it looks: during 2.1's fixture work, auto-detect turned French-accented English into French text entirely. A user deliberately practicing a non-native language is exactly the case auto-detect gets wrong.
  - The prompt now says "Speak only {label}, even if the user says something in another language" — the explicit clause is there because a small model drifts back to English without it.
  - **`language` is required on `POST /api/session/start`** (422 if omitted, 400 if unsupported) rather than defaulting to English, so a frontend bug can't silently produce English audio for a French session. This is a deliberate breaking change to 3.3's request contract; the only caller is our own frontend.
  - The scenario schema's `target_language` is now **vestigial** for prompt purposes — the session's chosen language wins. Left in the schema deliberately to avoid breaking 3.1/3.2's contract and their tests; worth removing in a future cleanup if it causes confusion.
- **Verification:**
  - 48/48 backend tests pass (10 new in `test_languages.py`), including: the endpoint's shape, language stored on the session, unsupported/missing language rejected, the prompt naming French and *not* English, the language reaching both STT and TTS, each language resolving a distinct voice, and per-voice cache keying.
  - **Real end-to-end French session, live:** generated genuine French speech (`say -v Thomas`, "Bonjour, je voudrais réserver une table pour deux personnes"), started a `fr` session against the running stack, and got back a correct French transcription, an in-character French reply from the LLM, and 480KB of audio — in ~18.5s.
  - **Proved the voice actually followed the language**, two ways: only `fr_FR-siwis-medium.onnx` was downloaded into the container (the English voice was never fetched for that session), and transcribing the generated reply audio back with auto-detection returned French text matching the reply.
- **Known limitation (not a defect of this story):** the default `llama3.2:1b` model produces noticeably rough French ("que vous préférez-vous pour l'entretien des boissons ?"). Non-English practice will want a larger `OLLAMA_MODEL`.
- **NOT verified — needs a human in a real browser:** AC#2's forced choice (start button staying disabled until both a language and a scenario are picked), the picker resetting on "End session", and the language showing in the conversation header.
- **Outcome:** backend complete and live-verified in French; held at `review` pending a browser pass on the picker UX.
