# 7.2: Choose a Difficulty Level

**Story ID:** 7.2
**Epic:** 7 — Model Configuration & Difficulty
**Slug:** difficulty-levels
**Status:** review

> Added after the original backlog completed. Sized to one dev-day (~2-8h).
> No story points.

## Story

As a **user**,
I want **to choose a difficulty level on the main menu**,
so that **the AI uses simpler words when I pick a lower level instead of always speaking the same way**.

## Acceptance Criteria

1. `GET /api/difficulties` returns exactly four levels, each with a code, a label and a short hint.
2. The main menu forces a level choice: the start button stays disabled until a language, a level and a scenario are all selected.
3. `POST /api/session/start` requires a `difficulty`, rejects an unknown one with a clear 4xx, and stores it on the session.
4. Each level injects a distinct instruction into the LLM prompt — the four levels must not produce the same prompt.
5. A lower level demonstrably constrains vocabulary and sentence length; the beginner instruction asks for the simplest words and short sentences, the advanced one asks for no simplification.

## Tasks / Subtasks

- [ ] Add a difficulty registry with a per-level prompt instruction (AC: #1, #4, #5)
- [ ] Add `GET /api/difficulties`, registered on the router (AC: #1)
- [ ] Accept + validate `difficulty` on session start and store it (AC: #3)
- [ ] Inject the level's instruction into the composed prompt (AC: #4, #5)
- [ ] Add a level picker as step 2 of the main menu and gate the start button on it (AC: #2)

## Dev Notes

- The scenario files already carry a `difficulty` field, but it was **only ever a badge on a card** — it never reached the model, so it changed nothing about how the AI spoke. [Source: bmad-output/stories/3.1.scenario-schema-loader.story.md]
- Difficulty therefore becomes a per-session user choice, exactly like language did in 6.1, and the scenario field joins `target_language` as vestigial metadata kept only to avoid breaking 3.1/3.2's schema contract. [Inference]
- The value of the feature lives entirely in the prompt instruction: the level must tell the model what vocabulary, sentence length and tenses to use, not merely name a level. [Inference]
- Levels are labelled against CEFR (A1/A2/B1–B2/C1+), which is the standard reference for language learners in Europe. [Inference]

## Testing

- **Approach:** integration tests through the FastAPI `TestClient` capturing the prompt actually sent to the LLM, plus a live check that a real model visibly changes register between levels.
- **Key scenarios:** the endpoint lists four levels in order; a level is stored on the session; an unknown level is rejected; beginner and advanced produce recognisably different instructions; all four produce distinct prompts.
- **Per-AC verification:** AC#1 → GET and assert four ordered codes; AC#2 → manual browser check of the disabled start button; AC#3 → POST with a bogus level, assert 4xx, and assert a valid one is stored; AC#4 → capture prompts for all four levels and assert they're all different; AC#5 → assert the beginner prompt asks for short sentences and no idioms, and the advanced one asks not to simplify.
- **Fixtures / mocks:** mocked STT/LLM/TTS reusing 2.4's patterns, with a spy capturing the prompt.
- **Edge cases to cover:** a session started before the levels list loads; an unknown level code.

- **Implementation notes:**
  - Four levels: Beginner (A1), Elementary (A2), Intermediate (B1–B2), Advanced (C1+). Each carries a `prompt_instruction` that names concrete constraints — sentence length in words, which tenses, whether idioms and subordinate clauses are allowed — because a vague "speak simply" does not reliably steer a small model.
  - **Removed the per-scenario difficulty badge from the cards.** Showing "beginner" on a scenario while the user had chosen "Advanced" would have put two competing notions of difficulty on one screen. The field stays in the API and schema (no breaking change), it's just no longer rendered.
  - The menu is now three forced steps: language → level → scenario.
- **Verification:** 7 new tests (71 total, all passing), including one asserting all four levels produce *distinct* prompts — the guard against the feature being cosmetic. **Live proof with the real model**, same scenario and same audio, only the level changed:
  - *Beginner* → "Hello. Welcome. What can I get for you?" (8 words)
  - *Advanced* → 64 words, with "establishment", "complimentary beverage", "peruse our menu", "thus far"
- **NOT verified — needs a browser:** the level pills' appearance and that the start button stays disabled until all three steps are chosen.
- **Outcome:** working and live-verified; `review` pending a visual pass.
